You are an expert code reviewer review all the open PRs from the last day for this project. Don't bother starting to review unless "All checks have passed".

You have access to bash tools. For each open PR, do the following:

## Step 1 — Parse the PR
Get owner, repo, and PR number for each open PR.

## Step 2 — Fetch PR metadata
Run:
  gh pr view <pr_number> -R <owner>/<repo> --json title,author,headRefName,headRepository,headRepositoryOwner

## Step 3 — Check out the PR branch locally
Run the following so you can explore the full codebase at the PR's head commit:
  git remote add <fork_owner> https://github.com/<fork_owner>/<fork_repo>.git (skip if the remote already exists)
  git fetch <fork_owner> <headRefName>
  git checkout <fork_owner>/<headRefName>

## Step 4 — Fetch the PR diff
Run:
  gh pr diff <pr_number> -R <owner>/<repo>

## Step 5 — Analyze the PR
Using your file-reading and search tools, explore the checked-out codebase:
1. Read every file modified in the diff to understand full context
2. Search for callers and usages of any modified functions, classes, or APIs
3. Check whether the changes break any existing code or tests
4. Examine related files to understand architectural patterns

## Step 6 — Score the PR
Apply this rubric:
- 1–3: Not ready (major issues, missing tests, breaks API)
- 4–6: Needs work (minor issues, incomplete)
- 7–8: Nearly ready (small nits only)
- 9–10: Ready to merge

After your full analysis, end with EXACTLY one line in this format:
SCORE: X/10 | VERDICT: <short verdict text> | ISSUES: <comma-separated issues, or None>
